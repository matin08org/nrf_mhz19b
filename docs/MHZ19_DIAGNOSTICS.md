# تشخیص گیرکردن عدد CO2 روی ۵۰۰۰

این نسخه فقط ابزار تشخیص اضافه می‌کند؛ کالیبراسیون سنسور، ABC، رنج اندازه‌گیری
و مقدار CO2 را تغییر نمی‌دهد. فرمان UART همان 0x86 در 9600 8N1، با گرم‌شدن
۱۸۰ ثانیه و درخواست هر ۲ ثانیه است. فرمت بستهٔ NRF تغییری نکرده است.

فریمور build/CO2_Node.hex برای نود STM32F030F4P6 این مخزن است؛ برای برد اصلی
STM32F412 نیست. فایل ELF همین ساخت را برای مشاهدهٔ متغیرها در دیباگر استفاده کنید.

پس از گرم‌شدن، این مقادیر را با هم ثبت کنید:

| متغیر | معنی |
|---|---|
| watch_uart_ppm | مقدار بایت‌های ۲ و ۳ آخرین پاسخ UART، حتی اگر پاسخ نامعتبر باشد |
| watch_uart_header_ok | هدر آخرین پاسخ FF 86 بوده است |
| watch_uart_checksum_ok | checksum آخرین پاسخ صحیح بوده است |
| watch_uart_frames | تعداد پاسخ‌های کامل UART؛ باید افزایش یابد |
| watch_valid_frames | تعداد پاسخ‌های پذیرفته‌شده؛ باید افزایش یابد |
| watch_co2 | آخرین مقدار پذیرفته‌شده که به مسیر ارسال داده می‌رود |
| watch_report_valid | اعتبار نتیجهٔ درخواست اخیر |
| watch_sample_age_ms | عمر آخرین نمونهٔ پذیرفته‌شده |
| co2_sensor.last_frame | کپی پایدار ۹ بایت آخرین پاسخ کامل؛ در نمایش HEX بررسی شود |
| co2_sensor.bad_headers/bad_checksums/timeouts/uart_errors | شمارنده‌های خطا |

watch_uart_ppm فقط وقتی با header_ok=1 و checksum_ok=1 و افزایش شمارندهٔ پاسخ‌ها
همراه باشد شاهد دادهٔ تازهٔ سنسور است. در فریم خراب هم ممکن است بایت‌های خام
معادل ۵۰۰۰ باشند؛ این به معنی نمونهٔ پذیرفته‌شده نیست. rx_buffer هنگام DMA
ممکن است نیمه‌پر باشد؛ برای تشخیص از last_frame استفاده کنید.

- پاسخ تازه و معتبر با بایت‌های 13 88: خود سنسور در UART عدد ۵۰۰۰ فرستاده است.
- پاسخ تازه و معتبر با مقدار کمتر ولی watch_co2 برابر ۵۰۰۰: مسیر گزارش بررسی شود.
- watch_co2 متغیر ولی نمایشگر ثابت: بستهٔ NRF، اعتبار/عمر داده و نسخهٔ گیرنده بررسی شود.
- شمارنده‌ها ثابت یا خطاها افزایشی: تغذیه، زمین مشترک، سیم‌بندی UART و بازیابی بررسی شود.

در بررسی سخت‌افزار، محدودهٔ تغذیه و توان لحظه‌ای را با دیتاشیت دقیق سنسور
تطبیق دهید. وجود ۵ ولت در حالت بی‌بار، افت ولتاژ حین کار را رد نمی‌کند.
کالیبراسیون صفر خودکار در این نسخه انجام نمی‌شود؛ علت گیرکردن باید ابتدا مشخص شود.

تست میزبان پاسخ معتبر ۵۰۰۰ سپس ۴۲۰، checksum خراب، نگه‌داری نمونهٔ قبلی،
بستهٔ NRF و timeout را پوشش می‌دهد. عبور آن اثبات سلامت سنسور روی دستگاه نیست.
